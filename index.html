Abstract

Recent video-to-3D foundation models such as VGGT achieve state-of-the-art reconstruction by jointly attending to all input frames, but the resulting global attention scales quadratically with sequence length and exhausts a 16 GB GPU at roughly thirty frames. We present TTM (Temporal Token Merging), a fully training-free add-on that compresses cross-frame attention through three complementary techniques:

  • M1Layer-Selective Storage keeps intermediate features only at the four layers the prediction heads read, removing ~80% of stored activations.
  • M2KV-Asymmetric Merge attends with full-resolution queries against merged keys/values — no error-prone unmerge step, no token contamination.
  • M5Epipolar-Constrained Merge gates token similarity by the epipolar residual, using camera poses from a cheap low-resolution pre-pass of the same model.

All components reuse the frozen VGGT weights, need no fine-tuning, and stack with efficient-attention kernels such as FlashAttention.

The memory wall

VGGT alternates frame attention (tokens of one image) with global attention over all N = S\cdot P tokens of all S frames. That global step is what makes the predictions multi-view consistent, but its score map is N\times N: doubling the number of frames quadruples the cost. Drag the sliders to see how big the map gets at 518 px input (P = 1369 patches + 5 special tokens).

Analytic count of attention scores for one head of one merged global layer (BF16). Kernels like FlashAttention avoid materialising this map, but the compute still scales the same way — and TTM's savings multiply with theirs.

Method

TTM only touches VGGT's alternating-attention loop. Frames are tokenised as usual; inside the 24 blocks, the global attention of every non-tap layer from layer 5 on uses merged keys/values, only the four layers the DPT heads tap are stored, and an optional low-resolution pre-pass supplies the camera poses that drive the epipolar gate.

Cross-frame bipartite token merging

For each pair of adjacent frames (t, t{+}1) we project patch tokens with VGGT's own frozen key projection, L2-normalise, and match every even-indexed source token in frame t to its most similar token in frame t{+}1:

The top-n sources are merged. Because the score lives in the attention's own key space, no extra network is needed. We use hard-kept merging: soft averaging leaks frame t{+}1 content into frame t's slot and blurs depth.

M2 KV-Asymmetric Merge — no unmerge

The usual recipe is merge → attend → unmerge: the shortened sequence must be scattered back to every original position afterwards, and that broadcast bakes frame t{+}1 features into frame t's positions. But the quadratic cost comes from the key/value length, not the query length — each query yields exactly one output regardless of how many keys it sees. The output already has one row per original token, so the heads get exactly what they expect. Cost drops from O((SP)^2) to O(SP\cdot S(P-n)).

M1 Layer-Selective Storage

VGGT keeps the output of all 24 blocks for its heads, but the DPT depth/point heads only read \mathcal T = \{4, 11, 17, 23\} and the camera head only reads the last one. Storing None for the other 20 is a one-line change that frees ~870 MB at S=20, growing linearly with S, with bit-identical outputs.

M5 Epipolar-Constrained Merge

Appearance alone is ambiguous: a facade full of identical windows gives many look-alike keys. Geometry is not — the true twin of a patch must lie on its epipolar line in the next frame. M5 gates the similarity with the distance to that line:

The poses come from VGGT itself: a Pass 0 at 224 px (TTM with M1+M2) costs about a tenth of the main pass; its poses build F, and Pass 1 at 518 px reuses the same gates in all 20 merge layers. Follow-up: does each layer need the same budget?

Mid-depth global blocks attend in a sharply heterogeneous way — each query latches onto a small, distinct set of keys. A one-forward attention-heterogeneity probe (per-query coverage c_\pi and top-k Jaccard distance) ranks blocks without labels or per-layer sweeps, and suggests a per-block multiplier r^{(\ell)} = \alpha_\ell\, r_{\max} that merges less where correspondence is concentrated.

Honest finding: on Tanks and Temples all schedules land within ~0.2 F1 of each other (avg. F1@×5: uniform 54.63, mid-conservative 54.55, mid-aggressive 54.41, U-shape 54.61). KV-asymmetric merging is robust to where it is applied — the budget matters more than its shape.

Limitations

  • Merging relies on temporal redundancy; sparse, wide-baseline image sets offer less to merge.
  • The DPT tap layers keep full attention, so their cost is not reduced.
  • M5 adds a second (low-resolution) forward pass; with degenerate relative pose the gate falls back to 1.
